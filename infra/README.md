# Local mirror

A docker compose stack that keeps a durable, offline copy of your radar and serves the same page against it.

**It is a mirror, not a replacement.** The Claude artifact's database stays the source of truth, and the weekly scan is a Claude scheduled task that writes into that database. The summaries, affinity scores and limitations are generated by Claude, so the stack cannot run a scan itself. Use it for:

- history and backups you control (Postgres volume plus dated JSON snapshots),
- reading and filtering your data offline,
- a place the scheduled task can copy its results to after every run.

## What runs

| Service | Image | Holds |
|---|---|---|
| `db` | `postgres:16-alpine` | one `docs` table: a row per artifact document (`papers/<id>`, `conferences/<id>`, `journals/<id>`, `meta/*`, `data/users/local/*`), JSONB payload, version counter. Volume `pgdata`. |
| `app` | built from `./app` | serves `dist/radar.html` with a small runtime shim (`/shim.js`) and a JSON API. Volume `files` holds `snapshots/` (a full export is written before every import). |

The page is not rebuilt in the container: it mounts `../dist/radar.html`, so `python site/build.py` is all it takes to update the UI.

## Run it

```bash
python site/build.py                  # builds dist/radar.html
cd infra
cp .env.example .env                  # set POSTGRES_PASSWORD
docker compose up -d --build
```

Open <http://127.0.0.1:8787>. The port is bound to localhost only; Postgres is not published.

## Put data in

Either source works; both are idempotent (existing documents get a new version).

```bash
# 1. An export from the site (Topic & scans -> Export, format research-radar/v1)
curl -X POST --data-binary @../data/radar-data-2026-10-14.json http://127.0.0.1:8787/api/import

# 2. A folder of <collection>/<doc>.json files, as Claude's ArtifactData writes with out_dir
docker compose run --rm -v "/path/to/export:/in:ro" app node import.js /in
```

`data/users/**` (API keys, read marks) is never imported from a folder.

## Get data out

```bash
curl http://127.0.0.1:8787/api/export > radar-export.json     # same research-radar/v1 shape as the site export
docker compose exec db pg_dump -U radar radar > radar.sql     # full database
docker run --rm -v infra_files:/f -v "$PWD:/o" alpine tar czf /o/files.tgz -C /f .   # snapshots
```

## Differences from the Claude artifact

The shim implements `db`, a single local `user` (always editor) and `downloads`. It does **not** provide `sample` ("Propose topic with Claude") or `mcp` ("Run now"). Those controls report as unavailable. Changes you make here (marks, topic edits) live only in the mirror and are overwritten by the next import of the same document.
